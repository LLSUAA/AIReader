# 读见产品路线图

> 状态：CURRENT / 路线图 SSOT  
> 版本：0.2  
> 更新日期：2026-08-27  
> 本文是验证顺序，不是发布日期、功能承诺或自动开发清单。所有阶段均受 Owner 真实使用结果约束。

## 1. 当前问题

读见当前是可自用原型。陪读与本地阅读链路可用，全书框架提取可以运行，但尚未证明它在不同题材和格式下足够可靠，也尚未证明它能稳定帮助 Owner 完成真实内容闭环。

当前优先问题是：

> 读见能否把用户导入的材料转成可核对的理解，并让 Owner 在真实阅读、修正和表达中反复使用？

不是先建设完整“认知工作台”，也不是先决定商业模式。

## 2. 路线总览

| 顺序 | 验证目标 | 最小产出 | 进入下一步的条件 |
|---|---|---|---|
| R0 | 可靠提取 + Owner 真实内容闭环 | 跨题材质量记录；Owner 的阅读—提取—人工核对—内容产出记录 | 识别出稳定价值、失败类型与真正高频的人工动作 |
| R1 | 最小人工校准 | 保留 AI 原结果的最小编辑/删除/修正方案 | 质量问题确实可由人工修正解决，且 Owner 愿意反复使用 |
| R2 | 轻量观点卡 / Creator Brief | Markdown 模板与实际创作验证 | Owner 能从修订结果形成可用认知产物或创作素材 |
| R3 | 轻量 Challenge | 固定 Prompt 或检查清单 | 它能帮助发现反方、隐含假设或证据缺口，而非只增加对话 |
| R4 | 候选外部 ICP 验证 | 5–10 名候选用户的安装、使用与访谈记录 | 出现持续使用或明确付费意愿的证据 |
| R5 | 进一步产品化与商业化决策 | 明确做/不做的证据记录 | 仅在 R4 结果足以覆盖维护与支持成本时进入 |

Owner 使用验证贯穿 R0–R4，不是后期独立阶段。信任资产可以与真实自用和外部验证并行积累，但不能替代用户证据。

## 3. 近期阶段

### R0：可靠提取与 Owner 内容闭环

目标：先知道当前提取在什么材料上可信、在哪些地方失败，以及这些结果是否真的帮助内容生产。

- 完成至少 5 种题材或结构差异明显的样本核验；
- 每本记录章节覆盖、论断依据、概念失真、失败块、降级路径、耗时和实际模型；
- Owner 使用现有 Markdown 导出与手工模板完成若干真实文章、视频或研究笔记；
- 记录人工最常改什么、哪些输出被采用、哪些步骤没有价值；
- 将“约 30 分钟”视为测量项，而不是产品承诺。

不在本阶段为未来能力新建数据库、复杂 UI、图谱或自动化内容生成器。

### R1：最小人工校准

仅当 R0 表明“人工修正是稳定高频需求”时，设计最小校准能力：

1. 保留模型原始结果；
2. 支持编辑、删除、新增或修正框架条目；
3. 记录用户修订与必要来源上下文；
4. 导出时区分模型原结果与用户确认内容。

人工校准是用户认知资产，不是默认上传或开发者训练数据。第一版不做富文本、协作、云同步或版本图谱。

### R2：轻量观点卡与 Creator Brief

目标：验证“用户确认后的认知产物”是否能够降低内容表达的启动成本。

第一阶段只允许 Markdown 模板和工作流验证，候选字段可以包括：

- 核心命题；
- 作者观点与我的判断；
- 关键证据、反证与待核验问题；
- 可用案例与跨语境连接；
- 内容结构建议与来源提示。

不创建专用数据库、复杂 UI、独立生成中心或自动发布能力。观点卡、证据、异议和 Creator Brief 都是候选表现形式，不是预先确定的系统核心数据模型。

### R3：轻量 Challenge

Challenge 是观点压力测试方法，而不是大型沙盘或护城河。它应围绕用户已经写下的判断，使用固定 Prompt 或检查清单询问：

1. 核心观点是什么？
2. 依赖哪些隐含假设？
3. 最强反方如何反驳？
4. 证据与反证各是什么？
5. 出现什么事实时应修改观点？
6. 是否混淆概念、因果、时间尺度或样本范围？

不建设多 Agent、状态机、推演树、评分系统或复杂 simulation engine。

### R4：候选外部 ICP 验证

在 Owner 已跑通真实闭环后，找 5–10 名候选研究型创作者或深度阅读者进行小规模验证。重点观察：

- 他们实际使用哪一段工作流；
- 是否愿意处理本地文件和 BYOD 配置；
- 哪些人工动作值得产品化；
- 是否持续使用；
- 是否存在合理的付费意愿。

不得把安装量、粉丝量或个别称赞当作产品市场验证。

### R5：有证据后再决定产品化与商业化

只有 R4 出现持续使用与明确价值证据后，才讨论工作流收费、买断、年费或其他模式。按书收费不是默认路径；云端订阅、支付、会员和社群也不因商业想象提前建设。

## 4. 暂缓与不做

- CFI 精确定位修复：保留实验性章节/段落跳转，不阻塞可靠提取；
- 云账号、云同步、服务器代理、SaaS 后台、支付、会员；
- 移动端、社交、粉丝系统、自动发布；
- RAG/向量数据库、多 Agent、复杂知识图谱、大型沙盘；
- 全功能笔记软件、Readwise/Notion 替代品、通用 AI Chat；
- 为“更强模型”“更多 token”“更多书”本身建立收费层；
- 将用户本地校准默认为平台训练数据。

## 5. 每次进入开发前的门槛

每个候选功能都必须回答：

1. 它是否帮助用户从原始材料形成自己的、可核对的认知产物？
2. 它对应了 Owner 或候选用户的哪一个真实失败案例？
3. 能否先用 Markdown、Prompt、手工流程或现有存储验证？
4. 是否突破本地优先、BYOD、版权、安全渲染与低维护边界？
5. 是否需要同步更新架构、数据迁移、验证方案和 CHANGELOG？

无法回答第 2 项时，优先继续验证，不进入实现。
